## 二、Richfolio 可借鉴功能详解

### 功能 1：技术指标计算面板

**竞品实现方式**

Richfolio 在 `src/fetchTechnicals.ts` 中从 yfinance 获取 1 年日线 OHLCV 数据，然后纯手写 TypeScript 函数计算以下指标：

- **SMA50 / SMA200**：简单移动平均线，用于判断金叉/死叉
- **RSI(14)**：相对强弱指标，14 周期
- **MACD**：EMA12/EMA26/Signal9，含交叉信号和柱状图
- **Bollinger Bands**：SMA20 ± 2 倍标准差，含 %B 值和带宽，检测 squeeze（带宽收窄）
- **ATR(14)**：平均真实波幅，Wilder's 平滑法
- **Stochastic %K/%D**：14/3 参数
- **OBV**：能量潮，用最近 10 期线性回归判断趋势方向
- **衍生信号**：金叉/死叉判断、动量分类（STRONG_UP/UP/NEUTRAL/DOWN/STRONG_DOWN）、7 日/30 日低点检测、7 日成交量变化

所有计算无外部技术分析库依赖，直接从原始价格数据计算。计算结果以结构化对象返回，被 AI 分析和邮件渲染同时使用。

**我们当前现状**

`lib/charts.py` 中仅有 matplotlib 图表（1 个月股价 + 20d/50d MA），不输出任何技术指标数值。`USMarketProvider` 不获取也不展示技术指标数据。AI 生成每日总结时完全缺乏技术面参考。

**引入方案**

1. 新建 `lib/technicals.py`，定义 `TechnicalIndicators` 类
2. 使用 yfinance 已有的 `history(period="1y")` 获取 OHLCV 数据
3. 可选方案：
   - **方案 A**：引入 `ta` 库（`pip install ta`），一行代码即可计算 RSI/MACD/Bollinger 等
   - **方案 B**：用 pandas 手写计算（与 richfolio 同思路），无新依赖
4. 在 `USMarketProvider.get_holdings_data()` 中调用，将指标结果加入 report JSON
5. 在 `email_base.html` 中新增技术指标展示区域
6. 将技术指标数据注入 AI 生成总结时的上下文

**预估改动**：~150 行新代码（technicals.py）+ ~30 行集成改动

### 功能 3：Earnings Calendar Guard

**竞品实现方式**

Richfolio 在 `src/guards.ts` 中实现 6 步校验管道，其中与财报相关的：

1. 获取每个 ticker 的 `calendarEvents.earnings.earningsDate`（来自 yfinance）
2. 计算距财报日的天数
3. 规则：
   - 距财报 ≤ 3 天 → 强制将 AI 建议降级为 HOLD
   - 距财报 ≤ 7 天 → 禁止出现 STRONG BUY
4. 在 AI 分析阶段注入此约束："if earnings are within N days, be more cautious"

其他 5 步校验包括：ticker 合法性、价格在合理范围、AI 建议与数据方向一致、避免频繁翻转建议、置信度与信号强度匹配。

**我们当前现状**

无任何 Earnings Guard 或 Post-AI 校验机制。AI 生成总结时无财报日约束。

**引入方案**

1. 在 `USMarketProvider.get_holdings_data()` 中，用 `ticker.calendar` 获取未来财报日期
2. 在 SKILL.md 的 Step 6（生成每日总结）指令中注入约束："对距财报日 N 天内的持仓，提示财报风险"
3. 可选：新建 `lib/guards.py` 实现程序化校验

**预估改动**：~50 行（获取财报日期 + prompt 约束注入）

### 功能 4：52-Week Range 位置信号

**竞品实现方式**

Richfolio 在 `src/fetchPrices.ts` 中计算 `fiftyTwoWeekPosition`：

```typescript
const high = summaryDetail.fiftyTwoWeekHigh;
const low = summaryDetail.fiftyTwoWeekLow;
const position = ((price - low) / (high - low)) * 100; // 0-100%
```

用于：
- 邮件中的 52 周范围条形图（进度条样式）
- AI 分析上下文："near 52-week low, potential value entry"
- 底部钓鱼模型（Bottom-Fishing）：52 周低位 + RSI 超卖 + 缩量 = 买入信号

**我们当前现状**

`USMarketProvider` 已获取 `ticker.info` 但未提取 `fiftyTwoWeekHigh/Low`。holdings 卡片中无此信息。

**引入方案**

1. 在 `YFinanceClient.get_info()` 返回值中增加 `fiftyTwoWeekHigh`、`fiftyTwoWeekLow` 字段
2. 在 `USMarketProvider.get_holdings_data()` 中计算位置百分比
3. 在 `market.py` 的 `render_section()` 中增加 52 周范围条形图（CSS 进度条）
4. 将位置百分比注入 AI 总结上下文

**预估改动**：~30 行

### 功能 7：国会议员交易追踪

**竞品实现方式**

Stock-Email-Alert 在 `politician_tracker.py` 中实现：

1. **数据源**：两个公开 S3 托管的 JSON 数据集
   - 众议院：`house-stock-watcher-data.s3-us-west-2.amazonaws.com/data/all_transactions.json`
   - 参议院：`senate-stock-watcher-data.s3-us-west-2.amazonaws.com/aggregate/all_transactions.json`
2. **筛选逻辑**：只保留购买交易（`type == "purchase"`），金额大于阈值（默认 $50,001），时间在 lookback 天内（默认 45 天）
3. **去重机制**：`seen_trades.json` 用 composite key（politician + ticker + date + amount + chamber）记录已通知的交易
4. **AI 分析**：对每笔交易，Claude 分析：
   - 该议员所在委员会
   - 可能受益的相关立法
   - 时机模式（是否在法案投票前买入）
5. **输出**：独立邮件（橙色主题），每个交易卡片包含议员信息、交易详情、AI 分析

**我们当前现状**

完全无此功能。这是一个独特的信息源，市面上几乎没有竞品提供。

**引入方案**

1. 新建 `lib/politician_tracker.py`
2. 用 `requests` 从 S3 获取公开数据（无需 API key）
3. 按收件人 holdings 中的 ticker 筛选相关交易
4. 将相关交易注入 report JSON
5. 在 `email_base.html` 中新增"国会交易"板块
6. 可选：在 AI 总结中提及相关国会交易

**预估改动**：~200 行新代码（politician_tracker.py）+ ~50 行集成改动 + 模板更新

### 功能 8：SEC EDGAR 内部人交易增强

**竞品实现方式**

Stock-Email-Alert 在 `insider_tracker.py` 中实现：

1. **CIK 映射**：从 SEC `company_tickers.json` 获取 ticker → CIK 编号映射，本地缓存 7 天
2. **Form 4 检索**：用 CIK 从 SEC EDGAR 的 `submissions/CIK{number}.json` 找到最近的 Form 4 文件
3. **XML 解析**：解析 Form 4 XML，提取：
   - 交易人姓名、职位（Director、Officer、10% Owner 等）
   - 交易类型（Code "P" = 公开市场购买）
   - 股票数量、单价、总金额
   - 交易日期
4. **筛选**：只保留公开市场购买，金额 ≥ $25,000
5. **输出**：结构化的 insider purchase 列表

**我们当前现状**

`YFinanceClient.get_insider_transactions()` 使用 yfinance 的 `ticker.insider_transactions`，返回最近 90 天的交易概要。数据粒度较粗，可能不包含精确金额和交易类型 code。时效性可能不如 SEC EDGAR 直接查询。

**引入方案**

**方案 A（推荐）**：作为 yfinance 的补充数据源
1. 新建 `lib/edgar_client.py`
2. 对 holdings 中的 ticker，查询 SEC EDGAR 获取最近 14 天的 Form 4 购买
3. 与 yfinance insider transactions 合并去重
4. 在 holdings 卡片的"内部人交易"区域展示更详细的数据

**方案 B**：完全替换为 SEC EDGAR
1. 用 EDGAR 替代 yfinance 的 insider transactions
2. 更可靠但增加外部依赖

**预估改动**：~150 行新代码（edgar_client.py）+ ~30 行集成

### 功能 13：Pydantic 结构化 AI 输出校验

**竞品实现方式**

Stock-Email-Alert 使用 Pydantic 模型验证 AI 输出：

```python
class StockRec(BaseModel):
    ticker: str
    company: str
    current_price: float
    direction: Literal["BUY", "SHORT"]
    confidence: Literal["High", "Medium", "Low"]
    reasoning: str
    catalyst: str
    risk: str
    price_target: Optional[float]

class MarketAnalysis(BaseModel):
    buy_recommendations: list[StockRec]
    short_recommendations: list[StockRec]
    hot_sectors: list[HotSector]
    market_summary: str
    market_outlook: str
    vix_commentary: str
```

Claude 返回的 JSON 被 `MarketAnalysis.model_validate_json()` 校验，格式错误时直接报错而非生成损坏的内容。

**我们当前现状**

AI 生成的每日总结是自由格式 HTML 字符串，无结构化校验。如果 AI 输出格式异常，可能导致邮件渲染问题。

**引入方案**

1. `pip install pydantic`
2. 新建 `lib/schemas.py`，定义 AI 输出的结构模型
3. 在 SKILL.md Step 6 中要求 AI 输出符合 schema 的 JSON
4. 在 `send_report.py` 中校验 AI 输出，格式错误时重试或 fallback

**预估改动**：~80 行新代码（schemas.py）+ ~20 行集成

## 四、相关平台参考价值

### OpenBB（65K stars）

**定位**：完整的投资研究平台（CLI + SDK + Web UI），覆盖股票、期权、加密、外汇、宏观、另类数据等。

**可参考**：
- **数据模型设计**：OpenBB 的 `openbb.equity.price.quote()` 等统一接口设计，可以启发我们 `DataProvider` 的 API 设计
- **多源聚合策略**：OpenBB 支持多个数据源的同一数据类型自动切换，我们的 `DataProvider` 已实现类似思路

**不适合引入**：太重，仅安装就需多个依赖，且作为 skill 不适合引入如此庞大的平台。

### yfinance（23K stars）

**当前状态**：已是核心依赖。

**值得关注的 API**：
| API | 用途 | 当前是否使用 |
|-----|------|-------------|
| `ticker.calendar` | 财报日期 + EPS/营收预估 | ❌ 未使用 |
| `ticker.recommendations_summary` | 汇总评级 | ❌ 未使用（用 `recommendations`） |
| `ticker.history_metadata` | 交易时段信息 | ❌ 未使用 |
