## 4. CI/CD 流水线

### 4.1 持续集成 (CI)

**流水线阶段：**

```yaml
stages:
  - pre-check:
      - 代码检查 (ESLint / Pylint)
      - 风格检查
      - 安全扫描

  - build:
      - 依赖安装
      - 代码编译
      - 资源打包
      - 产物生成

  - test:
      - 单元测试
      - 集成测试
      - 代码覆盖率
      - 性能基准测试

  - quality-gate:
      - 代码质量分析
      - 漏洞扫描
      - 依赖审计
      - 许可证检查

  - package:
      - 容器镜像构建
      - 镜像安全扫描
      - 推送到仓库
      - 生成版本标签
```

**CI 最佳实践：**
- 快速反馈：流水线总时间 < 10 分钟
- 并行执行：并行运行独立任务
- 增量构建：仅构建变更部分
- 缓存策略：依赖缓存以加速构建

### 4.2 持续部署 (CD)

**部署阶段：**

```yaml
stages:
  - deploy-to-staging:
      trigger: 合并到主分支
      run: |
        - 部署到预发环境
        - 数据库迁移
        - 冒烟测试

  - manual-approval:
      environment: 生产环境
      run: |
        - 通知利益相关方
        - 等待批准

  - deploy-to-production:
      run: |
        - 蓝绿/金丝雀部署
        - 健康验证
        - 成功通知
```

### 4.3 部署架构


| 指标 | 目标 | 告警阈值 | 严重级别 |
|--------|--------|-----------------|----------|

| 磁盘使用率 | < 80% | > 90% | P2 |

### 7.4 日志

**日志级别：**

| 级别 | 用例 | 示例 |
|-------|----------|---------|

| DEBUG | 详细故障排除信息 | API 请求详情 |

### 8.2 恢复流程

**数据库恢复：**
```bash
# 1. 停止应用
npm run stop

# 2. 恢复数据库
pg_restore --clean --if-exists -d [数据库] [备份文件]

# 3. 运行迁移
npm run migrate

# 4. 验证数据
npm run db:verify

# 5. 启动应用
npm run start
```
